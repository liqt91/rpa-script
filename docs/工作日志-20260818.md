## 二、随机端口 + 安全加固 + 密码功能彻底移除

用户决策：本机工具免登录（彻底移除密码功能）、随机端口防冲突、扩展自动适配。

### 随机端口（8100-8199）

- `main.py`：`RPA_PORT` 显式固定优先，否则 8100-8199 选空闲端口；启动后写 `data/backend.port`
  （扩展/插件发现入口）；忽略旧 .env 的 PORT=8000。
- **浏览器扩展**（`background_base.js`）：`getBackendUrlWithDiscovery` —— storage 缓存端口优先，
  失败则 8100-8199 分块并发探测 `/health`，命中写回 storage；start / onclose 重连 / keepAlive /
  reconnect 消息全走发现；options 页端口可留空=自动发现。
- **DSH 插件**（`lib/index.js`）：`resolveBackendUrl` —— backendUrl 配置优先，否则读端口文件
  （RPA_DATA_DIR / ~/.dsh/rpa-data / backendCwd/data）；每次请求解析（后端重启换端口自动适配）；
  spawn 后 `waitForBackendReady` 轮询就绪。

### 安全加固

- 默认绑定 127.0.0.1（`RPA_HOST` 可覆盖）。
- CORS 收窄：仅 127.0.0.1/localhost/[::1] 任意端口（含 DSH web），外部站点无法跨源读取。
- Host 头白名单校验中间件：防 DNS rebinding（evil.com / 127.0.0.1.evil.com → 400）。
- SECRET_KEY 兜底：无/占位（your-secret-key-change-me）时生成随机值持久化 `data/secret.key`。

### 密码功能彻底移除

- 删除：admin_router（登录页/登出）、auth_router（login/password API）、admin_templates、
  前端 AdminPassword / AdminDashboard、修改密码入口、登出链接。
- `auth.py` 简化：`get_current_user` 直接返回 admin 默认身份（兼容各处依赖）；JWT/bcrypt 校验逻辑移除。
- `rpa_console.html`：去登录框，API 走相对路径（同源免认证）。
- DSH 插件：`createApi` 去掉 ensureToken/login/Bearer（免认证直连）；Config 的 token/username/password
  保留兼容、标注弃用。

### 验证

- 随机端口 8100 生效 + backend.port 写入；health/editor/rpa-console/workflows/elements 全 200。
- /api/auth/login、/admin/login → 404（已移除）。
- Host 校验：evil.com、127.0.0.1.evil.com → 400；正常 Host → 200。
- CORS：evil origin 无 allow-origin；localhost:8100 与 127.0.0.1:3080 → 允许。
- 前端构建产物无修改密码/退出登录；清理 15 个历史残留 bundle（emptyOutDir 被文件锁部分失败）。

## 三、端口自动切换验证（插件/扩展零配置跟随）

后端从 8100 换到 8111（杀旧起新，**不重启 dsh web、不 reload 扩展**）：

- 插件 `rpa_status` → backend ok（自动读新端口文件 8111）。
- 扩展 → online（WS 断线后 discovery 探测新端口重连）。
- 结论：后端任何一次重启换端口，插件（每次请求动态解析端口文件）与扩展（断线探测）均自动跟随。

### 排查发现

1. **"双后端进程"假象**：uv 创建的 venv 其 `python.exe` 是 shim（实际解释器在 uv 缓存目录），
   启动时出现 shim + 实际解释器两个 python 进程，但只有一个真实后端 —— 按命令行匹配会误判为两个后端。
2. **autoStartBackend 与手动启动竞态**：插件激活时探测后端（若恰好没起）会 spawn → 与手动启动竞争。
   已把 profile 配置 `autoStartBackend: false`（后端统一手动管理）；若改回 true 则不要手动起后端（二选一）。
