## 二、随机端口 + 安全加固 + 密码功能彻底移除

用户决策：本机工具免登录（彻底移除密码功能）、随机端口防冲突、扩展自动适配。

### 随机端口（8100-8199）

- `main.py`：`RPA_PORT` 显式固定优先，否则 8100-8199 选空闲端口；启动后写 `data/backend.port`
  （扩展/插件发现入口）；忽略旧 .env 的 PORT=8000。
- **浏览器扩展**（`background_base.js`）：`getBackendUrlWithDiscovery` —— storage 缓存端口优先，
  失败则 8100-8199 分块并发探测 `/health`，命中写回 storage；start / onclose 重连 / keepAlive /
  reconnect 消息全走发现；options 页端口可留空=自动发现。
- **DSH 插件**（`lib/index.js`）：`resolveBackendUrl` —— backendUrl 配置优先，否则读端口文件
  （RPA_DATA_DIR / ~/.dsh/rpa-data / backendCwd/data）；每次请求解析（后端重启换端口自动适配）；
  spawn 后 `waitForBackendReady` 轮询就绪。

### 安全加固

- 默认绑定 127.0.0.1（`RPA_HOST` 可覆盖）。
- CORS 收窄：仅 127.0.0.1/localhost/[::1] 任意端口（含 DSH web），外部站点无法跨源读取。
- Host 头白名单校验中间件：防 DNS rebinding（evil.com / 127.0.0.1.evil.com → 400）。
- SECRET_KEY 兜底：无/占位（your-secret-key-change-me）时生成随机值持久化 `data/secret.key`。

### 密码功能彻底移除

- 删除：admin_router（登录页/登出）、auth_router（login/password API）、admin_templates、
  前端 AdminPassword / AdminDashboard、修改密码入口、登出链接。
- `auth.py` 简化：`get_current_user` 直接返回 admin 默认身份（兼容各处依赖）；JWT/bcrypt 校验逻辑移除。
- `rpa_console.html`：去登录框，API 走相对路径（同源免认证）。
- DSH 插件：`createApi` 去掉 ensureToken/login/Bearer（免认证直连）；Config 的 token/username/password
  保留兼容、标注弃用。

## 三、端口自动切换验证（插件/扩展零配置跟随）

后端从 8100 换到 8111（杀旧起新，**不重启 dsh web、不 reload 扩展**）：

- 插件 `rpa_status` → backend ok（自动读新端口文件 8111）。
- 扩展 → online（WS 断线后 discovery 探测新端口重连）。
- 结论：后端任何一次重启换端口，插件（每次请求动态解析端口文件）与扩展（断线探测）均自动跟随。

### 排查发现

1. **"双后端进程"假象**：uv 创建的 venv 其 `python.exe` 是 shim（实际解释器在 uv 缓存目录），
   启动时出现 shim + 实际解释器两个 python 进程，但只有一个真实后端 —— 按命令行匹配会误判为两个后端。
2. **autoStartBackend 与手动启动竞态**：插件激活时探测后端（若恰好没起）会 spawn → 与手动启动竞争。
   已把 profile 配置 `autoStartBackend: false`（后端统一手动管理）；若改回 true 则不要手动起后端（二选一）。

## 六、overlay：UIA 无障碍树网页拾取（tdSelector 同款，零扩展/零后端）

用户目标：本地 UIA 捕获网页元素，独立于扩展/后端/CDP 端口。

### 原理

Edge/Chrome 把网页 DOM 暴露为 UIA 无障碍树：`Chrome_RenderWidgetWin_1` 窗口 → 渲染根
`Chrome_RenderWidgetHostHWND`（Name='Chrome Legacy Window'）→ `DocumentControl`
（AutomationId='RootWebArea'）→ DOM 节点（class=CSS 类名、ControlTypeName=EditControl/GroupControl…）。
用 UIA 深搜「含光标的最深有价值节点」即可拾取网页元素，生成与 tdSelector 同款特征链。

### 改动（`scripts/capture_gui/overlay.py`）

- 新增 `_uia_web_dom_at(x,y)` —— 从元素爬到渲染根，再做「含光标优先 DFS」直达最深 DOM 节点
  （O(深度×兄弟数)），`parents` map 用于回构 根→叶 路径；`max_depth=40 / max_nodes=1500` 预算。
- `_uia_parent_chain` / `_uia_node_dict` 基础辅助；`_WEB_DOM_ROLES` / `_BROWSER_UI_CLASSES`
  角色白名单 / 浏览器骨架过滤；`_is_web_dom_node` 判定。
- `_uia_web_capture(x,y)` 入口（工作线程 + `UIAutomationInitializerInThread` + `_UIA_QUERY_TIMEOUT` 限时）。
- `_build_element_info` browsers 分支：先试 `_uia_web_capture` → 命中置 `element_type='web'` 及
  `dom_path/path/rect` 并返回；否则 fall through 原有 UIA 逻辑。`_capture_via_extension`（web-mode 兜底）保留未删。
- `store.py` 已含 `candidates/dom_path/elem_attrs/page_url` 字段，web 元素可正常持久化。

### 已知缺口（已交付，留待后续）

- hover 高亮对浏览器窗口仍短路为整窗（捕获时才能细化）。

### 验证

## 八、方案评审：网页元素 UIA 捕获与定位（不改代码）

用户实测后提出三个探讨并确认「先写方案文档，不改代码」。产出 `docs/方案-网页元素UIA捕获与定位.md`：

1. **Q1 UIA→CSS/XPath**：能做。Chromium UIA 树与 DOM 可逆映射（ClassName→.class、AutomationId→#id、
   ControlTypeName→tag、Name→文本/aria、兄弟 index→nth）。限制：只对有语义节点，纯视觉 div 需回退父级/图像。
   **现写入 bug 根因**：`_build_element_info` web 分支硬编码 css_selector/xpath/candidates 为空。
2. **Q2 为何框得比 tdSelector 大**：hover 路径 `_uia_hit_rect` 对浏览器窗口短路（`_is_browserish_hwnd → return None,None`）
   → 回退整窗；捕获才下钻细粒度。修复方向：hover 对浏览器也走含点 DOM 深搜。
3. **Q3 解耦**：自建 WebSocket 非唯一；**CDP**（浏览器自带 /json + webSocketDebuggerUrl）即最小可测模型，
   无需自建 WS 与扩展，经 Runtime/DOM 域拿真 CSS/XPath。推荐分层：本地 UIA → CDP → 扩展（可选增强）。
   tdSelector 即 Windows UIA + 内置 Playwright 驱动并存的现成例证。

文档含数据格式设计（web_selector 非空 + candidates 兼容现有 css/xpath/drission 三族）与四个备用改动点（A 生成器 / B 写入修复 / C hover 细化 / D 分层抽象），待评审后实施。
