# 工作日志 2026-08-27

## 一、背景：浏览器指令「编译+重载」痛点

用户提问：改浏览器插件指令，每次都要编译重载，能否避免。经排查，真正痛点不是「编译」（已被
`rpa_new_command` 全自动执行），而是**编译之后要手动开 edge://extensions 点「刷新扩展」**——打断了
"让 AI 干活"的顺畅体验。用户预期：新增指令后不需要手动重载插件。

## 二、方案 C 实测：`new Function` 动态注入被 MV3 CSP 拦截（判死）

先做了最小可验证原型：后端 WS 下发 handler 源码 → background 转发 → content script 用 `new Function`
动态注册 handler。

- 注入链路本身**完全打通**（后端 → background → content → `__rpaInjectHandler`）。
- 但 `new Function` 被 CSP **硬拦截**（两次独立复现，报错一致）：
  ```
  Evaluating a string as JavaScript violates the following Content Security Policy directive
  because 'unsafe-eval' is not an allowed source of script:
  script-src 'self' 'wasm-unsafe-eval' 'inline-speculation-rules' ... chrome-extension://...
  ```
- **结论**：MV3 下 content script 隔离世界 + extension pages 均无法获得 `unsafe-eval`，
  「eval/new Function 动态执行任意 handler 源码」此路不通（manifest 的 `content_security_policy`
  硬性禁止声明 `unsafe-eval`）。

## 三、正确方案：自动重载插件（脚本替我点刷新）

改「手动重载」为「脚本自动重载」，全程免人工：

- `extension/background_base.js`：新增 `reloadExtension` action → `chrome.runtime.reload()`。
- `scripts/command_builder.py`：新增 extension 指令 build 完后，检测 `/api/workflows/runs/active`：
  - 无活跃流程 → 直接触发插件重载；
  - 有活跃流程 → 不打断，返回 `needs_extension_reload` + `active_runs` + `active_run_names`
    标记，交工具层提问用户「等（默认）/立即」。
- `rpa-dsh-plugin/lib/index.js`：`rpa_new_command` 拿到标记后附加 `__extension_reload_guidance`
  指引，让 agent 用 `ask_user_question` 问用户。
- **多浏览器**：`_trigger_extension_reload` 不硬编码 edge，改为 `GET /api/extension/status`
  遍历所有在线浏览器逐个 `POST /api/extension/command?action=reloadExtension&browser_type=<name>`；
  状态查询失败则回退广播所有。
- 端到端验证通过：WS 下发 `reloadExtension` → client_id 变化（扩展真实 reload）→ 自动重连。

**守卫语义**（用户拍板，非跳过）：有活跃流程时**提问用户**，默认等待执行结束；不静默跳过、不默认打断。

**编译这步的答复**：保留且已自动化。MV3 要求 content script 在 manifest 静态声明具体文件，
无法用「直接加载源文件」替代；`build_content_js.py`/`build_background_js.py` 拼接由
`rpa_new_command` 全自动跑，从来不是用户手动动作。

## 五、关键教训

- **CSP 红线**：MV3 下不要尝试 eval/new Function 动态执行插件代码，提前查 CSP 语义，避免整套原型白做。
- **沙箱启动后端会崩**：用沙箱 pwsh 启动后端，进程无法写工作区外的 `C:\Users\Administrator\RPA脚本\`，
  跑「小红书搜索」流程时 PermissionError 崩溃。后端必须用正常权限启动（现已恢复）。
- **扩展重载 vs 页面刷新的区别**：重载扩展（`chrome.runtime.reload()`）只更新扩展代码 + 重启
  background；已打开页面的 content script 仍是旧的，需页面 reload 才换新。background 类指令重载即生效，
  DOM 类指令靠流程里的 `launchBrowser`/`navigate` 自动注入新 content.js，多数场景无需手动刷页面。
