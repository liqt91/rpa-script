## 一、后端启动健壮性——消除「后端 30s 内未就绪」误报

### 现象

后端启动提示「失败: 后端 30s 内未就绪」，但 `rpa_status` 后端状态为 ok，疑似误报。

### 排查

- 插件 `startBackendProcess`（`rpa-dsh-plugin/lib/index.js`）：probe 失败才 spawn 并 `waitForBackendReady(30s)`；
  30s 内探测不到 `/health` 就报错。
- `backendCommand` 指向 venv 的 `python.exe`，而它是 **uv shim**，会 fork 出真正的解释器
  （`AppData\Roaming\uv\python\...`）。
- **根因 = 双后端残留竞态**：用 `/rpa-bridge/start-backend` restart 复现出 `8100 + 8101` 双实例。
  机制：
  1. `taskkill /T` 杀 shim，但 uv 真实解释器大子进程可能没被连根杀掉，旧后端仍占着 `backend.port` 指向的端口；
  2. 新后端起不了原端口 → `_pick_free_port()` 挑新端口（如 8101）并改写 `backend.port`；
  3. `waitForBackendReady` 在端口文件切换 / 旧进程半死期间反复探测旧端口 → 30s 探测不到就绪态 → 报「未就绪」；
  4. 结果新旧两后端并存。
- 另发现：spawn 用 `stdio:"ignore"`，后端启动失败的错误输出全部被吞，无从排查。

### 改动（`rpa-dsh-plugin/lib/index.js`，已提交 63c381b）

1. **后端日志落盘**：spawn 输出从 `stdio:"ignore"` 改为写入 `data/backend-run.log`，不再吞掉崩溃原因。
2. **子进程提前退出检测**：`waitForBackendReady` 每轮检查 `child.exitCode`，退出即立即判定失败，不再干等。
3. **超时放宽 30s→60s**（后端首启冷启动 + 依赖导入 + DB 迁移可能超过 30s）。
4. **失败给具体原因**：就绪失败时把 `backend-run.log` 尾部带进错误信息。

### 清理与验证

- 彻底停止双后端进程树（shim PID 用 `taskkill /T`），起恰一个后端 → `backend.port=8100`，`/health` ok。
- `rpa_status` 后端 ok、扩展在线；进程树干净（恰一个 shim + 一个解释器）。
- 结构测试 + lint 通过，已 push（`63c381b`）。

### 提醒

- **插件 JS 改动需重启 dsh web 才生效**（当前运行的是旧插件）。重启后启动失败会看到具体日志原因。
- 本机 `taskkill /T` 对 uv shim 的连根清理不可靠，是双后端残留来源；再遇启动失败按整棵树（shim PID 加 `/T`）清理。

## 四、统一捕获 P0 入口（DSH 最短路径）+ tdSelector 调研结论

### 目标

按 `docs/capture-unification-plan.md` 的 P0：让「捕获元素」走 DSH 最短路径——
对话一句话或 `/rpa_capture` 命令直接捕获，结果就地落当前流程工作区 `workflow.json` + `images/`。

### 关键调研结论（本轮实证）

1. **Chromium 不支持 `ObjectModelPattern`**：你提议的
   `IUIAutomationObjectModelPattern::GetUnderlyingObjectModel()` 通道实测
   `IsObjectModelPatternAvailable = False`——走不通，无法借此拿额外 DOM 属性。
2. **tdSelector 网页捕获是纯 UIA，不是 CDP**：扒 `selector.exe` 得
   `checkChromeCDP`/`playwright`/`connectOverCDP`/`pages[0]` 等，但那套是**运行时**用的；
   捕获元素的层级数据（`aaRole`/`ClassName`/`AutomationId`/`Text`/`ControlType`）与我们
   UIA 拿到的完全一致，层级从 `RootWebArea` 开始——**tdSelector 也没有 placeholder/value/data-***，
   它同我一样只给 UIA 子集。它「不弹新窗口在已开 Edge 捕获」是因为 UIA 对已开窗口直接工作。
3. **UIA 属性子集足够网页定位**：用 tdSelector 同款特征（`AutomationId:search-input` +
   `ClassName:textarea` + `Text`）跑我们 `web_selector.py`，产出 `#search-input`(100)/`[role=textbox].textarea`/
   `[aria-label=...]` 等——定位无虞。placeholder/value/data-* 对定位通常无用（会变、不通用）。
