## 五、存量指令清洗（质量门禁语义对齐 + 修复真实缺陷）

### 背景

`--all` 初跑把 41 个存量指令标红。逐类核实后确认：**大部分是门禁脚本与项目真实
执行语义不符导致的误报**，小部分是真实缺陷。

### 门禁脚本语义对齐（消除误报，对齐 extension_runner 真实约定）

- **复合/容器指令豁免**：if/while/for/break/continue/try/end* 由 emitter 展开，用
  `evaluate()` 或 `raise LoopBreak`，不走标准 execute → 不要求 execute/emit/extra_refs
  与 JSON params 严格对齐（`extension_runner._handle_compound` 处理）。
- **`resolve_vars` 规则移除**：runner 在调用 handler 前对整个 extra 统一
  `_resolve_vars`（`extension_runner.py:1145/1296`），execute 内单独调是冗余。
  0.3 节变量约定同步改写。
- **`$ref` 参数展开**：`_json_params` 改用 `resolve_params()` 展开，与 generate_commands
  一致（否则 mouseClickWin32 的 clickType 等被误判"JSON 没有"）。
- **electron 目录**：`electron_commands` 纳入 backend 合法 source 目录。
- **emit 规则细化**：非容器 backend/desktop 指令必须有 `runner.completed += 1`
  （completedSteps 计数）。

### 修复的真实缺陷（6 个非容器桌面指令漏 `runner.completed += 1`）

clickControlWin32 / clickElementUia / findWindowUia / inputControlWin32 /
inputElementUia / pickElementUia——execute 有 `_emit(stepComplete)` 但漏了
`runner.completed += 1`，会导致运行统计 completedSteps 计数不准。已全部补齐。

### 结果

### 背景

生成 setBrightnessWin32 的会话仍约 40 次交互。逐项核对后判定：**根因不是工具能力，
而是该会话没走命令化入口，退化成"手工读示例(12 次) + 手工跑生成器(3 次+撞沙箱) +
手工写临时测试(6 次) + 找端口(5 次)"**。工具 `command_builder.py` 本可一条命令吞掉
绝大多数这类动作，但 skill 没把它钉死为唯一入口（速查表写的还是 DSH 工具的
`rpa_new_command`，而独立会话可能没有 DSH 工具）。

### 改动（`skills/new-command/SKILL.md`）

- **速查表第 3 节改为 CLI 入口优先**：核心入口是
  `python scripts/command_builder.py <cmd> --definition-file <临时json>`
  （纯 python CLI，任何会话可跑，不依赖 DSH 工具）。4 步推荐流程：
  ①写定义到临时文件 → ②一条命令全链路（生成桩+构建JS+质量门禁+热重载）→
  ③填 execute → ④再跑命令复验到 quality_pass=true。
- **新增「🚫 三不要」硬约束卡**（速查表后、正文章前）：
  ①不要读示例文件（速查表已给最小模板）；
  ②不要手工跑 generate_commands/build_content_js（命令行内部自动）；
  ③不要写临时测试脚本（命令自带质量门禁 + 热重载校验；真要运行时验证用既有的
  handler_test_utils 的 run_handler）。
- **硬性约束 / 生成步骤 / 验证信号** 统一改为 `command_builder.py` 优先。

### 验证

- 用 `command_builder.py setBrightnessWin32`（已实现合格指令）实测：
  `ok=true`、`quality_pass=true`、`reload_pass=true`（reload handlers:75 + validate passed，
  一条命令完成注册+热重载+校验——正是该会话 40 次交互的核心产出）。
- 契约 passed；质量门禁 74/74 ALL PASS（含 setBrightnessWin32）；`harness:check` PASSED。
- skill version 1.3.0 → 1.4.0（registry 同步）。
