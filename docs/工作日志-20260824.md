## 一、elements.json 拆分落地（捕获写回与编辑器写入域分离）

### 背景

08-19 完成的统一捕获 P0 把捕获元素写进了 `workflow.json` 的 `elements[]`——但编辑器对
workflow.json 是整文档读-改-写（`WorkflowContext.commit`），捕获写进去的元素会被编辑器
下次保存用旧内存副本覆盖。按 `docs/capture-unification-plan.md` v2.2 协议拆分到
`elements.json`（用户已拍板）。

### 改动

**写侧（捕获/保存 → 只写 elements.json，不碰 workflow.json）**

- `scripts/capture_gui/store.py` `save_element_to_workspace`：
  落点改 `elements.json`（`{version:1, elements:[...]}`，同名替换，tmp+replace 原子写）；
  不再创建/修改 workflow.json。
- `src/runtime/routers/project_router.py`：
  新增 `_load_project_elements`（elements.json 优先 + workflow.json 遗留 elements[]
  按名合并兜底，不强制迁移）与 `_save_project_elements`（原子写 elements.json）；
  `project_save_element` / `project_register_image` 两端点切到新落点。
  `_load_workflow_data` 保留（供遗留合并）。

**读侧（合并读取）**

- `src/runtime/workflow/extension_runner.py` `load_project_workflow`：
  elements.json 优先 + workflow.json 遗留 elements[] 按名补齐 → element_map。
- `src/ui/workflow-editor/src/store/WorkflowContext.jsx`：
  新增 `readProjectElements`（同样的合并语义）；
  `loadWorkflow` / `loadElements` 项目模式改走合并读取。

**编辑器 commit（双写分离 + 惰性迁移）**

- workflow.json payload 不再携带 `elements`（只写 name/description/url/parameters/nodes）。
- 元素单独写 elements.json：**先**读最新盘（可能刚有捕获写入）→ 按名合并编辑器内存
  （磁盘优先，编辑器只补缺名）→ 原子写 elements.json，**再**写 workflow.json——
  中途失败时 workflow.json 的遗留元素仍在，可重试，无数据丢失窗口。
- 首次 commit 自动把 workflow.json 遗留元素搬进 elements.json（惰性迁移）。

**文案**

- `rpa-dsh-plugin/lib/index.js`：rpa_capture 工具描述 / /rpa_capture 命令描述与成功
  提示的 "workflow.json 元素库" → "elements.json 元素库"。

## 三、指令新增命令化（rpa_new_command）——确定性编排，零 LLM

### 背景

按深化方案①：新增指令流程要"确定性动作用命令固化、推理才走 LLM"。当前新增指令是
人记忆"何时跑哪个脚本"：`generate_commands.py` → 手写实现 → `build_content_js.py` →
重启。且 AI 代码生成只产代码块、需人复制粘贴。

### 改动

- **新增 `scripts/command_builder.py`（确定性编排执行体，零 LLM）**：
  ① 写 `commands/<cmd>.json`（definition 必需，或复用已存在文件）
  ② 跑 `generate_commands.py` 生成 Python 桩 + JS handler（幂等）
  ③ 跑 `build_content_js.py` 拼装 content.js（extension）
  ④ 校验新指令在 content.js / Python registry 就位
  输出结构化 JSON（每步状态 + 校验报告 + 产物路径）。
  支持 `--definition-file`（UTF-8 文件，规避 Windows 命令行中文 GBK 污染）。

- **`rpa-dsh-plugin/lib/index.js` 新增 `rpa_new_command` 工具**：
  参数 `{cmd, definition, skip_build_js, force}`；definition 经临时 UTF-8 文件传给
  command_builder（`runCommandBuilder` 辅助，同 `runCaptureOnce` 模式）。
  **确定性命令**：definition 给定则全自动跑完；真正要 AI 生成定义内容时，让模型先把
  definition 写进文件再调用本工具（LLM 只在"定义/实现"两点介入，脚本执行零 LLM）。

- **修复 `handler_validator.py` 默认路径 bug**：`extension/content.js`（不存在）→
  `dist/desktop/extension/content.js`（build_content_js 的真实产出地）。之前校验因
  找不到文件一直"跳过校验"。

### 验证

- command_builder 端到端：给定中文 definition → 生成 json/py/js 三产物，exit 0。
  二进制校验 `commands/<cmd>.json` 的 label 字节为正确 UTF-8（`\xe4\xb8\xad...`），
  确认中文链路无误。（首测乱码是 PowerShell 控制台/检查脚本显示层假象，非命令问题）
- 清理全部 `__test*`/`__enc*` 残留，还原 generate_commands + build_content_js。
- `harness:check`：**PASSED**；`test_elements_json_split` + `test_capture_element_kind`：**24/24**。
- 插件 `lib/index.js` 已同步两处 profile 副本。
