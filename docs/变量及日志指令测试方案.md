# 变量及日志指令测试方案

> 关联工作流：新建「变量及日志测试」｜浏览器：Edge（在线/自动拉起）｜目标站点：百度、example.com

## 目标

端到端实测「变量及日志」分类 2 个指令：`setVar`（设置变量）+ `log`（输出日志），并验证变量在整条链路的引用/传递：

- 纯后端赋值（全值类型）→ `{{变量}}` 拼 URL 进扩展指令 → 提取结果存变量 → 日志引用

已有单测 `src/runtime/tests/test_handler_backend.py`（setVar 字符串/整数/列表/引用 + log 引用，6 例），本次为真实运行实测。

## 边界

- **只记录问题，不修改代码**：不改动任何源码/配置/扩展/前端
- 仅操作：工作流节点数据（DB）+ 元素复制（DB）+ 触发运行 + 读取运行日志/结果
- 产出：问题清单（每步失败/异常/行为不符），不修复

## 指令参数（已核实）

| 指令 | 关键参数 | 说明 |
|---|---|---|
| setVar | name, value, valueType | valueType：文本(str-input)/数字(int-number)/布尔(bool-check)/列表(list-input)/字典(dict-input)/表达式(any-expr)/自动(any-input) |
| log | message, level | message 支持 `{{变量}}`；level：info/warning/error |
| launchBrowser | browserType, url, windowState, windowVar, bringToFront | url 支持 `{{变量}}` |
| getText | element_name(列), scope, resultVar | 结果存变量 |
| getElementLink | element_name(列), scope, resultVar | href 存变量 |
| navigate | windowVar, url, waitLoad | |
| closeBrowser | windowVar | |

## 已知实现点（观察基准）

- `setVar`：`convert_value` 按 valueType 转换；`any-input` 先 JSON 推断再退回字符串；表达式 `=expr` 前缀走 `_eval_expression`
- `log`：message 走 `resolve_vars` 替换 `{{var}}`；**未定义变量原样保留**（记录行为点）；结果 `{log, level}` 进 SSE + `data/run_logs/<wf>/<run_id>/run.log`
- 扩展指令输入在 `_resolve_vars` 解析 `{{var}}`；结果经 `resultVar/saveToVar/varName` 存回 `runner.vars`；窗口变量为 `{windowId, tabId}` dict
- ⚠ 观察点：`valueType` 存在两套定义（`commands/setVar.json` 用 string/number/code；handler 注册用 str-input/int-number/any-expr 等），以实际存储值为准记录

## 工作流编排（20 步）

### Part A 纯后端（节点 1-12，不依赖浏览器）

| # | 指令 | 参数 | 预期 |
|---|---|---|---|
| 1 | setVar | text1 = 你好世界 / 文本 | text1="你好世界" |
| 2 | setVar | num1 = 42 / 数字 | num1=42(int) |
| 3 | setVar | flag1 = true / 布尔 | flag1=True |
| 4 | setVar | list1 = ["a","b","c"] / 列表 | list1=["a","b","c"] |
| 5 | setVar | dict1 = {"k":"v"} / 字典 | dict1={"k":"v"} |
| 6 | setVar | expr1 = `=len(list1)+1` / 表达式 | expr1=4 |
| 7 | setVar | auto1 = 42 / 自动 | 记录：JSON 推断为 int? |
| 8 | setVar | ref1 = `{{text1}}` / 文本 | ref1="你好世界"（引用解析） |
| 9 | setVar | comb1 = `{{num1}}件` / 文本 | comb1="42件"（串内插值） |
| 10 | log | `文本={{text1}} 数字={{num1}} 布尔={{flag1}}` / info | 日志显示替换后内容 |
| 11 | log | `列表={{list1}} 字典={{dict1}} 表达式={{expr1}}` / warning | 列表/字典 str() 化显示 |
| 12 | log | `未定义 {{undef}}` / error | 记录行为：原样保留? |

### Part B 浏览器贯穿（节点 13-20）

| # | 指令 | 参数 | 预期 |
|---|---|---|---|
| 13 | setVar | targetUrl = https://www.baidu.com / 文本 | 供后续引用 |
| 14 | launchBrowser | edge / `url={{targetUrl}}` / normal / browser1 / bringToFront | Edge 打开百度（验证扩展输入变量引用） |
| 15 | getText | element=百度一下 / resultVar=text1 | 按钮文本存 text1（覆盖步骤1的值） |
| 16 | log | `提取到按钮文本: {{text1}}` / info | 显示提取结果 |
| 17 | getElementLink | element=a_s-top-username / resultVar=link1 / **onError=continue** | href 存 link1 |
| 18 | log | `提取到链接: {{link1}}` / info | 显示 |
| 19 | navigate | browser1 / https://www.example.com / waitLoad | 跳转（验证窗口变量 dict 传递） |
| 20 | closeBrowser | browser1 | 关窗收尾 |

> 步骤 17 用 `onError=continue` 是防御性设置：a_s-top-username 是登录态元素，未登录时可能不存在——保证单次运行把后续问题一并记录。其余步骤保持默认 stop。
> 风险：库内百度元素（2026-07 捕获）可能随页面改版失效——若 15 步失败即中断，改现场捕获后再跑（记录问题，不修代码）。

## 元素准备

1. DB 插入工作流 + 节点 + 元素复制

## 风险提示

- `any-input` 自动推断边界（"42"→int 还是 str?）
- 表达式 `=len(list1)+1` 依赖 list1 已定义（顺序依赖）
- 未定义变量原样保留（`{{undef}}`）是否符合预期——记录
- 库元素失效 → Part B 中断或提取为空——记录
