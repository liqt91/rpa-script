# 工作日志 2026-07-30

## 一、WebRPA 调研

### 1. 项目概况

调研了 [pmh1314520/WebRPA](https://github.com/pmh1314520/WebRPA)（1821 star），一款成熟的零代码 RPA 工具。

**技术栈：**
- 后端：FastAPI + Playwright（浏览器自动化）+ uiautomation（桌面）
- 前端：React + TypeScript + Vite + @xyflow/react（流程图）+ Radix UI + Tailwind
- 启动器：Electron + Vue 3（打包成单 exe，系统托盘/开机自启）
- 集群：orchestrator（节点注册/心跳/认领任务/上报结果）
- AI：Socket.IO 流式对话 + 技能注册表

**规模：** 260 个执行器、46 个 API 模块、70 个前端组件。

### 2. 与我们的架构对比

| 维度 | WebRPA | 我们 |
|------|--------|------|
| 浏览器 | Playwright CDP | Chrome Extension |
| 元素拾取 | JS 注入 + CSS 选择器 | Extension content script |
| 元素存储 | 无元素库（每次捕获） | WorkflowElement 元素库 |
| 列表循环 | nth-child 通配符 | anchor/child 标注 + 运行时相对定位 |
| 桌面拾取 | UIA 轮询 | Win32 XOR + UIA 双通道 |
| 已登录浏览器 | ❌ 无法复用（CDP 需重启） | ✅ 扩展直接控 |
| 指令架构 | 执行器大文件 | handler 模式（一指令一文件） |
| 前端 | React 成熟 | tkinter demo + React 半成品 |

### 3. 值得借鉴

- **@xyflow/react** 流程图编辑器（可替代手写画布）
- **orchestrator API 设计**（集群节点管理）
- **AI 助手** Socket.IO 流式交互
- **拾取体验** 蓝色高亮 + 绿色闪烁确认
- **桌面宏录制**（pynput 监听 → 自动生成步骤）

### 4. 不需要学的

- **Playwright** 替代 Chrome Extension（我们的扩展方案更强）
- **执行器大文件**（我们的 handler 模式更好）
- 他的元素拾取**成功率低**（百度搜索 3 次只成功 1 次，层级不一致、卡片被遮挡）

# 工作日志 2026-08-04

## 一、GUI 统一捕获 — 浏览器元素捕获链路打通

### 问题
- 桌面元素捕获已有（overlay.py），但浏览器 DOM 元素捕获链路一直不工作
- 扩展的 content_capture.js 已有成熟选择器生成，需复用

### 最终方案
GUI HTTP POST → FastAPI ext_manager → Extension WS → content_capture.js → 用户点击 → WS回传

### 关键发现
1. 扩展实际加载 dist/desktop/extension/ 目录（非 extension/），一直改错文件
2. __rpaCaptureInjected guard 阻止了第二次注入新脚本
3. ensureContentScripts 需要在 sendMessage 前调用
4. websockets>=13 默认拒绝所有 origin，需 origins=None

### 新增端点
- POST /api/extension/gui-browser-capture
- POST /api/extension/verify-selector

## 二、GUI Web 元素编辑器重写
