## 四、MCP 服务器落地（ADR-0011，commit 70efe2c）

用户提出「做 MCP 服务器，实现哪些功能」，plan 模式调研后拍板：双传输都要、含 P5 浏览器实时控制、首版 P1-P3 全做。

- **架构**：薄适配器——独立 stdio 进程 `src/mcp_server/`（fastmcp），经 httpx 调现有 FastAPI REST，JWT 认证走 `RPA_API_TOKEN`（或 RPA_USERNAME/PASSWORD 自动登录换 token）；不 import runtime/service，保持可独立部署/测试。
- **功能**：33 个工具分四档——P1 只读（workflow 查询/运行记录）、P2 创作（workflow CRUD）、P3 运行控制（run/pause/resume/stop）、P5 浏览器代理（单指令实时执行）；另 3 个 resources（workflow://、run://log）。`RPA_MCP_TOOLS` 环境变量白名单可裁剪工具组。
- **后端配套**：新增 `POST /api/extension/exec`（单指令执行，复用 ext_manager 的 requestId/future 模式，与运行中工作流互斥 409）与 `GET /api/extension/commands`（透出 handler 注册表，MCP 自动生成浏览器工具 schema）。
- **踩坑**：包名不能叫 `mcp`（遮蔽官方 SDK，pytest 收集即炸）→ 改名 `mcp_server`；PS5.1 重写中文文件乱码 → 改用 write 工具；fastmcp3 无 `list_tools`；`get_all_handlers` 裸表需 `build_command_registry`。
- **冒烟**：CRUD 闭环 + run wf=23 真实 3/3 通过；pytest 119 passed；ruff 0；结构测试 PASSED。
- **接入方式**（客户端配置）：stdio `python -m src.mcp_server.server`（cwd=仓库根，env 给 RPA_API_TOKEN）；或 streamable HTTP `python -m src.mcp_server.http`（127.0.0.1:8765/mcp）。已在会话中向用户说明 WorkBuddy 配置方法。
