## 三、W2 判定（条件中断）

- 两节 forList 体内的 ifVarEquals **每次迭代都崩**：`'bool' object is not subscriptable`（6 个 failed step）。
- if 节点 `onError=continue` 使流程存活，A/B 两节均把 3 个城市全部 log 出来（break/continue 从未触发）。
- 根因：`ifVarEquals.evaluate()` 返回裸 bool，而 `_handle_compound` 用 `eval_result["met"]` 取下标 → TypeError。
- B2（声明参数 `compareTo` 但 evaluate 读 `value`）被 B3 掩盖，即使修好 B3，compareTo 仍会被忽略（expected 恒为 ""）。
- 另坐实 P1：`failed=6` 但 run `success=True`。

## 四、W3/W3b/W3c 判定（浏览器循环）

| 节 | 预期 | 实际 | 判定 |
|---|---|---|---|
| forEachElement 遍历结果列表 | N 次迭代 | 百度、Bing 均 **0 次** | 失败 → B5 |
| whileCondition elementExists | 2 次（熔断上限） | 0 次（恒判不存在） | 失败 → B5 |
| whileCondition urlContains | 1 次后退出 | 0 次（恒判不含） | 失败 → B5 |
| launchBrowser / navigate / closeBrowser | 正常 | 正常 | 通过 |
| W3c waitForElement(bing li.b_algo) | 找到元素 | `appeared:true, matchedCount:10` | 通过（反证页面/扩展正常） |

**B5 根因**：后端 `_find_elements` / `_check_element_exists` / `_check_element_visible` /
`_get_element_text` / `_get_current_url` 调用的 5 个扩展 handler（`findElements` /
`checkElementExists` / `checkElementVisible` / `getElementText` / `getCurrentUrl`）在扩展侧
**完全未注册**（`extension/` 与 `dist/desktop/extension/` 均只有 16 个命令 handler）。
扩展 content 收到未知 type 回 `{status:'error', error:'Unknown step type'}`，后端这些
辅助方法把异常**吞掉只记 warning**，返回空/False → 循环静默 0 迭代、条件恒 False。
影响面：forEachElement、whileCondition(elementExists/elementNotExists/urlContains)、
ifElementExists/ifElementVisible/ifUrlContains/ifTextContains 等全部条件查询路径。
注意：`elementNotExists` 会因 `not False=True` 而**错误地恒真**。

## 六、非产品建议

- B5 修复方向：扩展侧补齐 5 个查询 handler（或后端改走已注册的 waitForElement/getText 路径）；
  后端辅助方法吞异常时应上报 stepError 而非静默降级。
- B3 修复方向：handler.evaluate 统一返回 `{"met": bool}`，或 `_handle_compound` 兼容裸 bool。
- B1/B2 修复方向：对齐 commands/*.json 与 handler Param 的参数名。
- B4 修复方向：emitter 对未注册指令发出明确错误或 warning。

### 已修复清单
- **B3**：`_handle_compound` 对 `_evaluate_condition` 结果边界归一化（非 dict → `{"met": bool(...)}`），if* 全部不再崩。
- **B5**：扩展新增 5 个 content handler（findElements/getCurrentUrl/checkElementExists/checkElementVisible/getElementText，位于 `extension/dom_handlers_new/`）；后端 5 个查询辅助方法去掉吞异常（M2 一并解决，错误上抛为 stepError）。
- **B1**：forList handler 兼容 `listVar`/`listName`；`commands/forList.json` 参数名改 `listVar`。
- **B2**：ifVarEquals 改读 `compareTo`（回退 `value`）。同类一并修：ifVarContains(substring)、ifTextEquals(compareTo 优先)、ifTextContains(substring)、ifListContains(listVar)、ifDictContains(dictVar)；`whileCondition` 目录与 handler 补 `maxIterations` 参数。
- **B4**：emitter 不再静默丢弃未注册指令；runner 对无 handler 指令显式 stepError（openBrowser 专属提示改用 launchBrowser）。`openBrowser` 指令已删除：ai_flow_builder 白名单/提示、CommandsPage.jsx、commands_table.md、两个示例流程（zhihu_flow.json、script_example/3_知乎竞品统计.json）全部迁移 launchBrowser；新增迁移 `_migrate_015`（DB workflow_nodes openBrowser→launchBrowser，删注册表遗留行），_SCHEMA_VERSION 14→15。补建了缺失的 `endLoop.py` handler 注册（此前靠静默丢弃掩盖）。
- **M1**：`_run_body` stepStart 补 cmdType/cmdLabel/compound。
- **M3**：`_summarize` 跳过等于参数默认值的项（whileCondition 摘要不再显示「表达式: False」）。
- **M4**：totalSteps/completedSteps 改事件计数（stepStart 计 total，stepComplete/stepError 计 completed），completed ≤ total。
- **M5**：`_ensure_connected` 无显式 browserType 时回退到在线扩展的浏览器类型；连接超时报文改为中性文案。
- **B6（回归中新发现）**：元素操作/提取 handler（clickElement/getText/getElementLink/hover/scrollIntoView/inputElement）的 `findTarget` 此前不做循环上下文解析 → 循环体内子元素全部解析失败。已改：`findTarget(locator, family, extra)` 有上下文时走 `reResolveWithContext`；`reResolveWithContext` 在循环项内未命中时抛 `contextNotFound`（不再静默退回全局 document）；监听器把 contextNotFound 转为「成功+标记」软结果，后端按 onError 策略处理（continue=空值+stepWarning 继续，stop=明确报错终止）；contextNotFound 结果存变量为空串。
- **getCurrentUrl 后台化**：新增 `extension/background_handlers/getCurrentUrl.js`（chrome.tabs.get 直读，不经 content），消除导航后 content 重注入窗口期与后端 5s 超时的竞争。

### 行为变化（需知晓）
- 未注册/废弃指令（custom、scrollToBottom、writeTableRow 等）从「静默跳过」变为「显式 stepError」。存量含这些指令的流程会在运行时报错提示。
- 循环体内子元素缺失：onError=stop 时现在会明确报「元素在当前循环项中未找到」（此前静默取空/取错元素）。
