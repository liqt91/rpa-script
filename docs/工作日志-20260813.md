# 工作日志 2026-08-13

## 一、hover 高亮「细粒度框选后偶发跳回整窗」— 滞回机制修复

用户报告：悬浮在 tab/文字上框选出细粒度元素后，过一会儿有概率跳回「框选整个应用」。

### 根因（真机 Windows Terminal / OpenCode 窗口复现）

- hover 的 UIA 深搜兜底（`_deepest_uia_element`）是**概率性**的：`max_nodes` 预算内访问不到深处的 tab/text 节点时，返回较粗的元素。
- 整窗矩形**恒包含光标**，所以 `_get_uia_rect` 里「光标仍在结果矩形内才采纳」的 containment 检查挡不住这种「细→粗」降级 —— 一旦新查询返回整窗，旧细粒度结果就被覆盖，高亮跳到整窗且无法恢复。

### 修复

- `_HoverWorker._query` 增加 `_hysteresis(x, y, rect)` 滞回判定：
  - 新查询返回无效/None：旧结果仍包含光标 → 沿用旧结果。
  - 新结果明显变粗（面积 ≥ 旧结果 4×）且光标仍在旧细粒度矩形内 → **不降级**，保留旧结果。
  - 否则采纳新结果。
- 新增 `_rect_contains(r, x, y, tol=2)` 辅助函数（overlay.py:1024）。

### 验证

- 滞回单元场景 6 例全 PASS；悬停抖动 200 帧（8px 抖动）0 次窗口级跳变，最终保持 tab `217×32`。
- 真实遮罩 E2E 抖动 6s 后捕获 tab `217×32`；`harness:check` PASSED。

## 二、Alt+点击捕获「只捕获，不操作」— WH_MOUSE_LL 吞点击钩子

用户报告：Alt+点击捕获仍会触发真实的点击效果，要求「只是捕获，不操作」。

### 根因

遮罩/悬浮窗是鼠标穿透的（`WM_NCHITTEST→HTTRANSPARENT`，且区域在光标处抠洞），所以 Alt+点击捕获、右键取消时，真实点击会穿透到下层应用，触发实际点击副作用（实测遮罩窗在点击处是整块洞，点击直达目标）。

### 方案：低级鼠标钩子吞掉点击

- `overlay.py` 新增 `_install_mouse_swallow_hook()` / `_uninstall_mouse_swallow_hook()`：`SetWindowsHookExW(WH_MOUSE_LL)`，回调对 L/R/M 键的 down/up 消息**返回非零直接吞掉**，点击在到达任何应用前被拦截。
- 钩子同时维护模块级手势状态：Alt+左键按下 → `"capture"`，右键按下 → `"cancel"`（`_consume_mouse_click()`），以及鼠标按住状态 `_mouse_down()` —— 因为**低级钩子吞掉的点击不会反映到 GetAsyncKeyState**（实测恒 0），捕获循环从钩子状态读手势，不再轮询按键。
- 安装线程必须有消息泵：`run_capture_mask` 主循环每帧 `_pump_messages()` 天然满足；`run_capture` 循环补上同样的泵取（否则钩子回调延迟到 Alt 松开后，Alt 检测失败）。
- 两处捕获入口（`run_capture` / `run_capture_mask`）进入循环前安装、`finally` 卸载（钩子是全局的，只在捕获期间生效，结束即恢复点击透传）。
- 修复钩子回调里的 `global` 声明缺失（内层赋值被当成局部变量，手势状态从不写回）。

### 验证（真机）

- 钩子安装后：下层接收窗 0 次点击；卸载后 1 次点击（恢复透传）。幂等安装/卸载正常。
- Alt+点击在 `run_capture` 与 `run_capture_mask` 两条链路都能触发捕获（OpenCode tab `217×32` / 整窗兜底均正常）。
- Esc 取消返回 `None`；`harness:check` PASSED。

## 三、全屏遮罩式捕获（desktop_mask）与配套加固

- 新增 `scripts/capture_gui/overlay_mask.py`：`_MaskLayer` 全虚拟屏 layered 半透明遮罩（压暗全屏 + 高亮目标镂空 + 蓝色描边），`run_capture_mask` 全流程（hover 复用 overlay worker / 桌面图标命中 / Alt+点击捕获 / Esc/右键取消防粘连）。
- `capture_once.py` 支持 `desktop_mask` 模式；`CaptureToolModal.jsx` 新增「捕获桌面元素新」按钮。
- 配套加固（`overlay.py`）：
  - **深搜含点优先 DFS**：含光标子节点排栈顶先访问，O(深度) 触达最深 tab/text，纯 BFS 在大树（Windows Terminal）上预算内够不到深层节点的问题。
  - **浏览器窗口豁免深搜**：`Chrome_RenderWidgetHostHWND` 等 DOM 内容区不在 UIA 树，深搜只会遍历数千节点（4-6s 超时）且找不到更细的 → 直接整窗兜底，网页细粒度走「捕获网页元素」通道。
  - **桌面图标单项命中**：SysListView32 走 LVM_HITTEST/LVM_GETITEMRECT/LVM_GETITEMTEXTW 跨进程消息（tdSelector 同款），UIA 对 FolderView 单项暴露差的问题。
  - **DPI 感知**：`SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`，双屏笔记本内外屏缩放不一致时坐标错位问题；虚拟屏边界判断（副屏坐标可为负）。
  - **悬浮窗对 UIA 不可见**：`RpaBorder`/`RpaInfo` 的 WndProc `WM_GETOBJECT→0`，根治 worker 的 `ControlFromPoint` 命中悬浮窗卡死；`WM_NCHITTEST→HTTRANSPARENT` 鼠标穿透。
  - **hover worker 细节**：仅坐标更新时查询（`seq` 防重复深搜打满 provider）；屏幕外坐标不投递（UIA `ControlFromPoint` 对屏幕外点永久卡死）；`_uia_draw_lock` 让 worker 查询与主循环绘制严格串行（互饿死问题）。
