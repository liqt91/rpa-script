## 问题清单（只记录，未修改代码）

### P1-① switchTab(urlPattern) 在 navigate 之后间歇性匹配失败
- **现象**：navigate 跳转到新 URL 后，紧接着的 `switchTab(urlPattern=新URL片段)` 偶发报「未找到匹配 URL 的标签页」，命中即中断后续步骤（onError=stop 默认）。
- **证据**：主流程 step6 失败；复现脚本第 1 次失败、之后 3/3 成功；无 pattern 的 switchTab 能返回正确 URL（`https://www.example.com/`），说明 navigate 已生效、tab URL 正确。
- **根因**：`switchTab`/`closeTab` 的 `chrome.tabs.query({windowId})` 读取到的 tab.url 与 navigate 后实际 URL 之间存在**时序竞争**（navigate 的 waitLoad 完成事件与 tab.url 在 tabs API 中提交的时机不同步）。
- **修复（已实施，2026-08-06）**：
  1. `extension/background_handlers/navigate.js`：waitLoad 之后加「URL 提交确认」轮询（`chrome.tabs.get` 校验 host 是否已切换，至多 5s），navigate 确认门牌挂好才返回
  2. `extension/background_base.js`：新增共享 `findTabByUrlPattern(windowId, pattern)` —— URL 匹配带重试（4 次 × 250ms）
  3. `extension/background_handlers/switchTab.js` / `closeTab.js`：改用共享 helper，匹配失败先重试再报错
  4. 重建扩展（`python scripts/build_extension.py`）
- **验证（修复后）**：
  - navigate→switchTab 压力测试（6 轮交替）**14/14 全过**
  - 主流程「浏览器操作测试」wf=10 重跑 **10/10 全过**（含原失败 step6 + 原未跑到的 closeTab/closeBrowser）
  - pytest 117 通过、结构测试通过
- **生效**：需浏览器 `chrome://extensions` 重新加载扩展

### 备注
- `switchTab`/`newTab`/`closeTab`/`closeBrowser` 的 `windowVar` 为 string 类型（非 str-var），background 实际回退用 `agent.workWindowId`/`workTabId`（launchBrowser 建立）——本测试全链路依赖该隐式状态，正常工作。
- `onError=stop` 默认导致单个步骤失败即中断剩余步骤；对测试类流程建议 per-step 观察或 onError=continue。
