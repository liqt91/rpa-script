## 二、UIA 解析通用化（微信黑屏 / 终端混合架构）

- **微信 UIA 黑屏/卡死**：微信 UIA provider 一被查询就黑屏卡死 → `_is_skip_uia`（wechat/weixin/wework 进程名跳过 UIA），hover/捕获均不查 UIA，退纯 Win32 信息
- **hover 轻量化**：`_get_uia_rect` 只取 `ControlFromPoint`+`BoundingRectangle`（不沿祖先取 Name/类型）——终端卡死正是重遍历触发
- **捕获限时 + 运行时黑名单**：`_try_uia_capture` 在工作线程执行（`UIAutomationInitializerInThread`），join 3s 超时 → 返回 Win32 信息并自动把该进程记入黑名单（通用兜底，不硬编码应用名）
- **Windows Terminal 混合架构（WinUI 3 XAML island）**：hit-test 返回 0x0 InputSite、真实控件只能从根走树 → 新增 `_deepest_uia_element`（`ElementFromHandle(WindowFromPoint)` 起步 + 有界 BFS，**不按节点 rect 剪枝**，取含光标最小元素）+ hover 节流缓存；捕获到 `TabItem`（`uia_path` 完整 → 落库自动 `element_type=uia`，可被 `clickElementUia`/`inputElementUia` 驱动）
- `pick_from_path` 顶层窗口定位补**类名匹配**（终端标题随激活标签变化）；移除 `_is_browser_window` 中 `CASCADIA_HOSTING_WINDOW_CLASS`（终端不再误标 web）
- 新增诊断探针 `scripts/capture_gui/probe_terminal_uia.py`（只读、分段超时、修掉 C.descend 剪枝 bug）；COM 初始化改 ctypes ole32（去 pywin32 依赖）

## 三、网页捕获：跟随标签页 + Esc 兜底 + 受限页等待 + 超时/悬浮框优化

- **跟随激活标签页**：`background_base.js` 记录 `guiCapture` 会话，`tabs.onActivated` 重瞄（退出旧页→进入新页，同一 requestId），`tabs.onUpdated` 载入完成重试（`captureActive` 防重入）
- **Esc 兜底取消**：overlay `_poll_esc_cancel` 线程 `GetAsyncKeyState` → `POST /gui-browser-cancel`（后端 `_gui_capture_futs` 注册表 resolve fut + 发 `exitBrowserCapture`）——不依赖 content 脚本（edge:// 受限页/载入中也能立即取消）
- **清理目标修对**：`exitBrowserCapture` 先取跟踪的 `guiCapture.tabId/prevTabId` 再清，向这些标签页 + 激活页发 `exitCaptureMode` → 超时/取消后**框选必清**
- **受限页启动不退出**：`launchBrowserCapture` 失败不再结束会话，发 `browserCaptureNote`；后端存 note，`/gui-browser-hover` 返回 `{hover, note}`，悬浮窗显示「当前页面无法捕获（受限页面），请切换到普通网页」
- **超时 20s → 300s**（固定，不再被突然打断；Esc 兜底取消）
- **悬浮框不躲鼠标**：`show_info` 抽出 `_move_info_window()`，`_poll_hover_thread` 每轮（250ms）重新躲避鼠标，文本变化才重绘
